# 入口：查询或导出预估利润

适用：按店铺、商品负责人及日期查询利润、逐月对比或生成利润 Excel。

读取 [每日预估利润口径](../profit-estimate.md)，按以下流程执行；员工和管理员都使用同一只读查询入口。

“过去 N 天”或“最近 N 天”以推广费最新完整日为结束日；月份按口径页解析为显式区间。查询使用已入库数据的时效，不盲目按电脑当天日期推算。

1. 用 `db access-check` 核对当前身份，`profit orders identity` 发现店铺键。读取已入库广告数据的日期覆盖，按口径页将自然语言时间解析为显式起止日期。员工不需要提供底层编号。
2. 执行 `profit estimate query --shop-key <KEY> --start-date <日期> --end-date <日期> --group-by <粒度> --json`。查询直接读取当前订单、退款、成本、运费、广告及负责人数据计算，不改变源数据。新表需要管理员授予 SELECT；权限错误交给管理员，不能换维护身份或绕过工具。
3. 全店汇总用 `shop`，负责人全区间合计用 `owner`，逐日用 `day`，全店逐月用 `month`，负责人逐月对比用 `owner-month`。负责人从当前结果发现；一个姓名用 `--owner`，多人用 `--owners`。未分配负责人单独披露，不丢弃金额或猜姓名。
4. 检查 `eligibleDates`、`skippedDates` 及订单/退款覆盖。缺广告日期不能视为零广告费；退款申请日覆盖不代表所有结算日已完整。缺失或不完整期间需明确披露，员工只报告缺项；管理员经授权才另行维护源数据。各组 `available_days` 是该组有行的天数，不证明全店覆盖。
5. 用户要求 Excel 时使用相同店铺、日期、负责人和费率执行 `profit estimate export --out <新路径.xlsx>`。验证六张表：摘要、负责人汇总、负责人月度对比、商品汇总、每日明细、计算规则。检查中文字段、金额和百分比格式，利润率按汇总利润/净销售额计算，不平均各行比率。
6. 交付实际日期、数据缺口、查询时间、费率、利润拆分和估算金额。结果为经营预估，不是正式月结；数据后续更新时再次查询可能不同。超时或权限失败停止并报告，不反复运行重查询。

完成后返回主 Skill 的 Company Warehouse Flow 交付结果。
