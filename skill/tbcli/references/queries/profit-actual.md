# 入口：月度实际利润与数据缺口

适用：计算或导出一个完整自然月的实际经营利润，或独立检查该月达到实际月结所缺的数据。

先读取 [月度实际利润口径](../profit-actual.md)，然后只进入用户请求的分支。计算、导出与数据缺口检查相互独立；完成分支后返回主 Skill 的 Company Warehouse Flow 交付 QA。

## 共同预检

1. 运行 `tbcli --help` 与 `tbcli capabilities --json --all`，检查请求分支所需的 `profit actual` 命令。缺失时返回 `CAPABILITY_UNAVAILABLE`，列出命令、输入和预期输出；不得使用估算利润、通用 `db query`、原始 SQL 或临时脚本替代。
2. 运行 `tbcli db access-check --json`。员工读取实际利润使用只读身份；数据导入和政策维护仍需管理员单独授权。
3. 运行 `tbcli profit orders identity --json` 发现店铺键。用户给出店铺名称时使用唯一匹配；零匹配或多匹配时停止请用户确认。
4. 将自然语言月份解析为唯一 `YYYY-MM`。实际利润只接受完整自然月，不把最近 N 天或任意日期段改称月结。
5. 默认使用 `operating-profit-v5`：订单头实付为收入总额，商品明细金额作为订单内归一化收入分配权重；平台费6%、税费2%、未匹配运单每单估算2元。子件原销售成本来自 `master.current_sku_costs.unit_cost × 订单子件数量`；未发货仅退款全额冲回对应数量的成本，退货退款按可二次销售比例暂估冲回，默认 50%，即使退货状态显示“待入库”亦按此人为参数计算。已发货仅退款和退款不退货保留原成本。`goodsCost` 与订单 `source_ref_unit_cost` 用于审计。缺失成本、退款行无法映射、退货待入库分别披露。全零且仅含 `dc99999` 的占位订单整体排除并披露数量。商品 `641773251256` 按补差价链接处理，负责人非必填且成本为 `explicit_zero`。`v4` 保留原退款成本口径，`v3` 使用收入占比运费分摊。
6. 按 [平台 SKU 毛重运费分摊口径](../profit-actual.md#平台-sku-毛重运费分摊口径) 核对当前重量主数据、组合子件映射、发货购买件数和覆盖状态。未发货退款数量不参与发货重量与运费分摊；退货退款属于已发货商品，仍参与运费分摊。区分单 SKU 直接估算、单未知 SKU 剩余重量推算和多未知 SKU 剩余净重均分；低置信度估计可参与分摊但须披露。无法获得有效重量的订单按有效发货数量加权的收入比例回退，并披露订单数、SKU 数和回退运费金额；负责人、商品及综合报告标记为 `provisional`。

## A. 计算分支

执行：

```bash
tbcli profit actual query \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  [--policy-version '<版本>'] \
  [--return-resale-rate <0..1>] \
  --group-by '<shop|owner|product|day|report>' \
  [--owner '<姓名>' | --owners '<姓名1,姓名2>'] \
  --json
```

- 全店用 `shop`，负责人用 `owner`，商品用 `product`，日趋势用 `day`。生成综合分析报告时优先用 `report`，一次取得 `sections.shop`、`sections.owners` 和 `sections.products`，避免重复计算与跨次结果漂移。
- 负责人从未筛选结果发现；未分配和无法归属项单独披露并保留在店铺总计中。
- 保留 CLI 返回的利润月、退款截止、政策版本、可二次销售比例、运行状态、成本同步批次、占位订单排除数、来源状态、质量摘要、原销售商品成本、两类退款成本冲回、净商品成本和行数。重新运行既往月份会用当前审核成本重新估值，应在报告注明。
- 明示本次运费分摊方法、重量来源、最近一次重量更新批次、单未知推算和多未知均分的 SKU 组数、缺重订单数、收入回退运费金额和低置信度 SKU 数。`v5` 的负责人和商品利润使用扣除未发货退款数量后的平台 SKU 毛重并披露回退；显式运行 `v4` 时标明原退款成本口径，运行 `v3` 时标明收入占比运费口径。
- `provisional` 结果可以用于经营判断，但必须披露参考/估算金额及占比；`incomplete` 只报告已知部分与缺口，不称为实际利润。

完成后返回交付 QA，不自动运行 coverage，也不补数据。

## B. Excel 导出分支

先对明确输出路径做只读存在性检查，然后执行：

```bash
tbcli profit actual export \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  [--policy-version '<版本>'] \
  [--owner '<姓名>' | --owners '<姓名1,姓名2>'] \
  --out '<新文件.xlsx>' \
  --json
```

要求文件存在、非空、可打开，并包含：摘要、负责人汇总、商品汇总、SKU汇总、订单商品明细、退款回挂、物流对账、数据质量、计算规则。核对 JSON 与工作簿中的店铺、月份、退款截止、政策版本、运行状态和总额。

完成后返回交付 QA，不自动运行 coverage 或导入。

## C. 数据缺口分支

执行：

```bash
tbcli profit actual coverage \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  [--policy-version '<版本>'] \
  --json
```

按来源分别报告订单与商品行、退款观察窗与回挂、承运商账单与运单匹配、推广费、成本、平台 SKU 毛重与组合映射、负责人和政策版本。对每项保留：需要范围、当前覆盖、actual/reference/estimated/explicit_zero/missing 状态、缺失对象或金额、是否阻断 `actual/reconciled`。

输出中的 `calculationPerformed` 必须为 `false`。订单头与商品行原始权重差额、退款头与明细差额、未匹配运单、缺成本行、推广缺日分别判断，不用单一“已导入”状态代替质量检查。订单头实付是选择后的收入金额，商品明细金额标记为分配权重；未匹配运单按每单2元归为 `estimated` 并披露数量与金额；缺失成本返回逐项清单；无法归属退款返回退款单号、旺店通订单号和平台订单号；未分配负责人返回商品ID、商品名称、SKU、ERP编码、订单数、金额和源数据可用的图片链接。

coverage 只报告缺口与已确认政策产生的估算金额。未经用户授权不下载、不导入、不改政策、不写主数据，也不选择新的回退方法。用户补齐一项后重新运行相同月份的 coverage，再继续下一项。

## D. 商品成本审计分支

当用户要核实旺店通订单行 `goodsCost` 是否等于 SKU 单位成本乘销售数量时，执行：

```bash
tbcli profit actual audit-cost \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  --product-id '<商品ID>' \
  --json
```

该命令逐订单商品行比较三套数字：旺店通订单行总成本 `goodsCost`、旺店通参考单位成本 `refCostPrice × skuNum`、支付日生效且已批准的 `master.sku_cost_versions.unit_cost × skuNum`。比较容差固定为 0.01 元，必须分别保留可比较、相符、不相符和数据缺失的行数；不能只比较合计，因为逐行差异可能互相抵消。

审计只验证成本来源的一致性，不执行利润计算、不改变成本优先级、不修改数据库，也不讨论负责人或物流分摊。输出逐行订单号、商品/SKU/ERP规格标识、数量、三套成本、两两差额和汇总覆盖。零行表示所选月份内该商品没有符合正式利润订单范围的明细，不能表述为商品不存在。

## E. 整张订单成本审计分支

当用户要判断组合 SKU 的零成本商品行是否会在整张订单汇总后抵消，或抽样核对全店订单成本时，执行：

```bash
tbcli profit actual audit-order-cost \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  [--order-nos '<旺店通订单号1,订单号2>' | --sample-size '<1-1000>'] \
  --json
```

指定 `--order-nos` 时核对这些订单内的全部商品与 SKU，并返回每个商品行的商品ID、SKU、ERP规格、数量、三套成本与差额；不指定时默认按订单号稳定抽样 30 单，同一批事实重复运行会得到相同样本，仅返回订单汇总以控制结果体积。逐订单比较订单行 `goodsCost` 合计、`refCostPrice × skuNum` 合计和支付日有效的已批准 SKU 成本合计。任一来源存在缺行时，该订单涉及该来源的比较标记为不可比较，不能用部分和宣称相符。

抽样结论只代表样本；需要保证全店月度成本时，扩大样本或执行全量核对。完成本分支后返回交付 QA，不改变正式利润成本优先级。

## F. 组合 SKU 成本审计分支

当用户要确认某个组合 SKU 的 `goodsCost` 为什么无法覆盖子件成本，或检查其他组合 SKU 是否存在同类异常时，执行：

```bash
tbcli profit actual audit-combo-cost \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  [--product-id '<商品ID>'] \
  [--platform-sku-id '<平台SKU ID>'] \
  --json
```

组合 SKU 的可验证定义是：同一旺店通订单内，同一商品 ID 与平台 SKU ID 展开为两个及以上不同 ERP 规格。命令按组合 SKU 汇总订单实例、ERP 子件、零 `goodsCost` 行、应有正成本却记零的行、三套成本合计、不一致订单数及示例订单。无筛选时盘点全店当月全部可识别组合 SKU；商品或平台 SKU 筛选用于复核单一对象。

命令只能证明旺店通导出的原始订单明细字段如何落值，以及异常是否扩散到其他组合 SKU。旺店通后台为什么生成该字段属于配置或产品逻辑判断；没有后台设置证据时必须表述为待核实原因，不能把数据相关性直接写成根因。

## G. 参考成本政策就绪审计分支

当用户要比较订单快照 `refCostPrice` 与历史时点已批准成本主数据的覆盖和一致性时，执行：

```bash
tbcli profit actual audit-reference-cost \
  --shop-key '<店铺键>' \
  --month '<YYYY-MM>' \
  --json
```

该命令排除政策已确认的 `explicit_zero` 商品后，核对参考单位成本的覆盖、零值、与支付日有效的已批准 SKU 成本主数据的逐行一致性，并返回缺失、零值和不一致对象。`refCostPrice` 非空不等于成本有效；参考成本为零且没有主数据可验证的商品必须继续作为待确认成本缺口，不能因 `goodsCost` 同样为零就推断真实成本为零。

该审计的 `readyForReferenceFirstPolicy` 仅回答订单快照成本能否作为潜在历史时点来源，不是当前成本政策的就绪门。当前政策的缺失成本以 `profit actual coverage` 的 `costs` 和 `profit costs reconcile` 结果为准；审计命令不改变正式利润公式或政策版本。

## H. 运费回退订单审计分支

当用户要判断尚未按平台 SKU 毛重分摊的订单对负责人利润的影响，并按缺口原因确定处理顺序时，执行：

```bash
tbcli profit actual audit-freight-fallback --shop-key '<店铺键>' --month '<YYYY-MM>' [--order-nos '<订单号1,订单号2>'] [--limit 30] --json
```

该命令只支持当前 `operating-profit-v4`，复用实际利润的订单、平台 SKU 组合映射、购买件数和运单费用口径，不计算或改写利润。不指定订单时，`summary` 覆盖该月全部回退订单，并与 `coverage.freightWeightAllocation` 的订单数、金额回勾。指定 `--order-nos` 时，汇总范围仅为这些回退订单，返回每个 SKU 的订单实际子件数量、当前组合定义、毛重、购买件数、账单计费重量及原始收入权重，供逐项核查。若同一商品的多个平台 SKU 共用子件，`jointPurchaseCandidates` 仅在每个 SKU 有唯一锚定子件且所有子件合并数量完全回勾时，给出购买件数候选；全部 SKU 毛重可用时，`candidateWeightComparison` 才展示只读的负责人运费差异。这些候选不改变当前利润政策，也不能把当前组合定义自动当作该历史订单的真实配置。`topOrders` 按运费绝对值排序，`priorityOrders` 优先显示跨负责人或负责人和未分配商品混合的订单，`--limit` 只限制返回明细条数。按 `byOwnerScope` 区分单一负责人、跨负责人、负责人和未分配混合、全部未分配；按 `byPrimaryReason` 给每单唯一主因，`byIssue` 可重复计数。负责人依据订单支付日已批准的商品归属。核查后再提出修映射、补毛重或保留收入回退的建议；不要从订单数直接推断利润差额。

## 交付 QA

- 明确说明本次进入计算、导出或缺口检查中的哪一个分支。
- 结果明确区分经营实际利润与平台结算时间口径财务利润。
- 报告店铺、月份、退款截止、政策版本和运行状态。
- 利润率用汇总利润除以汇总净销售额，不平均明细利润率。
- 负利润、负净销售、负向快递调整和无法归属退款不得删除或改成零。
- 命令缺失、权限失败、超时或质量门失败时停止并返回真实错误，不反复运行重查询。
- 成本审计必须同时报告逐行差异和三套成本的数据覆盖；`allComparableCostsMatch:true` 只有在所有可比较行都相符时成立，`fullyComparable:true` 才表示三套数据每行都齐全。
- 整单成本审计必须报告抽样方式、全月候选订单数、样本订单数、未找到的指定订单、三方可比覆盖和不一致订单；稳定抽样不能表述为全店全量保证。
- 组合 SKU 审计必须明确组合识别规则，并区分已验证的源字段异常、跨组合 SKU 范围和仍待旺店通后台验证的配置根因。
- 参考成本政策审计必须披露参考覆盖率、主数据可比率、零值、假零值、不一致行及待确认对象；不能把“全部可比行一致”表述为“全部订单行已经验证”。
- 运费回退审计必须披露全量回退运费、负责人结构、互斥主因与可重叠缺口，并与 coverage 回勾；同一负责人订单不改变该负责人利润，但可能改变商品利润。
