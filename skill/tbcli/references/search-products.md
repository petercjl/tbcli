# 按指定图片和搜索词采集商品列表

## 输入与执行

按调用者提供的图片、搜索词和页数采集商品列表。搜索内容、输入图片选择、关键词制定、采集范围及补搜计划均由调用者决定。需要 1–5 张已保存的 JPEG/PNG（单张最多 10 MiB）、1–10 个搜索词，以及新的 JSON 输出路径。URL 图片先保存到经过存在性检查的新文件，再交给命令。保留原始 URL 到研究输入清单。

```bash
tbcli search products --image ./product.jpg --keyword '寿司模具' --keyword '寿司炮筒' --max-pages 2 --out ./competitor-candidates.json --json
```

`--image` 和 `--keyword` 可重复。按输入顺序执行每个图片和搜索词，保留重复输入。`--max-pages` 只控制每个关键词的 1–10 页，默认 1。图片搜索固定首批商品 ID，逐屏加载这批主图，后续滚动追加的商品不纳入本批。每次重新运行必须选择新输出。

主线：检查登录与参数 → 复用搜索标签页 → 分词搜索及真实翻页 → 原标签页内逐图搜同款 → 保留各批商品记录 → 保存每批来源和候选 → 回读核对 → 返回调用者。无可复用的搜索/首页/空白标签时只创建一个，整次运行复用并保留它。图片与词分别执行并按批次顺序追加记录，平台页面当前不提供已验证的图片加文字联合过滤。

## 输出契约

`schemaVersion=2`、`strategy=image-and-keyword-batches`、`deduplicated=false`。`input` 保存图片名/哈希、搜索词和页数；`batches` 保存类型、图片序号/哈希或词、页码、时间、行数和停止原因。`products` 按批次和卡片顺序保留每条记录，`itemId` 为字符串且允许重复；`recordCount` 表示记录数。每条包含链接、标题、主图、搜索卡片价格、店铺、付款文案、地区和完整 `observations`。不同来源的价格和标题都保留在 observations。

商品去重、相关性判断与后续复核由调用者处理。旧 schemaVersion=1 为历史合并格式，新输出明确使用版本 2，消费者须核对契约。搜索卡片价格不是 SKU 到手价；付款文案不是标准周期销量。

## 失败与 QA

登录/验证码/访问限制立即停止，保留失败页面供人工处理；禁止刷新、绕过或自动重试。正常错误返回非零码，JSON `status=partial` 保留此前批次。超时/结构变化不能作为零结果；只有明确空结果文案才记零行。

回读检查 status、批次数、各来源、商品 ID 格式与记录数、图片哈希、缺字段、重复来源和停止原因。输出当前采样边界，由调用者决定后续请求参数。本命令不获取详情、SKU、评价、人群或销售报表，也不直接修改项目台账。

依赖 tbcli 当前 `capabilities` 中 `search products`；不存在时要求升级/开发组件，不用私有请求替代。调用者应动态加载当前 tbcli Skill，然后回到其“候选收集完成”节点。命令由当前源码提供；发布、套件更新和其他平台运行验证分别记录。
